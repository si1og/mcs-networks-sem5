\section{Задание 1. Разбиение IP-сети на подсети}

Требуется разбить исходную IP-сеть на 5 подсетей с заданным числом адресов в подсетях.

\vspace{1em}

\noindentИсходные данные для варианта 18:

\begin{itemize}
	\item исходная сеть: \mintinline{text}{194.3.192.0};
	\item маска сети: \mintinline{text}{255.255.255.0};
	\item по крайней мере 3 подсети должны включать по 32 адреса.
\end{itemize}

Запишем исходную маску сети в двоичном виде:

\begin{minted}{text}
11111111.11111111.11111111.00000000
\end{minted}

Первые 24 бита маски определяют адрес сети, а оставшиеся 8 бит отводятся
под адресацию внутри неё. Таким образом, исходная сеть содержит

\[
	2^8 = 256
\]

адресов. Разобьём это адресное пространство на одну подсеть, включающую
128 адресов, и четыре подсети, каждая из которых включает 32 адреса:

\[
	256 = 128 + 32 + 32 + 32 + 32.
\]

Такое разбиение образует 5 подсетей, полностью использует адресное
пространство исходной сети и удовлетворяет условию: не менее трёх подсетей
включают по 32 адреса.

Полученные подсети имеют следующий вид:

\begin{enumerate}
	\item Подсеть \mintinline{text}{194.3.192.0/25}:
	\begin{itemize}
		\item адреса узлов: \mintinline{text}{194.3.192.1}~-- \mintinline{text}{194.3.192.126};
		\item широковещательный адрес: \mintinline{text}{194.3.192.127};
		\item число доступных узлам адресов: $128 - 2 = 126$.
	\end{itemize}

	\item Подсеть \mintinline{text}{194.3.192.128/27}:
	\begin{itemize}
		\item адреса узлов: \mintinline{text}{194.3.192.129}~-- \mintinline{text}{194.3.192.158};
		\item широковещательный адрес: \mintinline{text}{194.3.192.159};
		\item число доступных узлам адресов: $32 - 2 = 30$.
	\end{itemize}

	\item Подсеть \mintinline{text}{194.3.192.160/27}:
	\begin{itemize}
		\item адреса узлов: \mintinline{text}{194.3.192.161}~-- \mintinline{text}{194.3.192.190};
		\item широковещательный адрес: \mintinline{text}{194.3.192.191};
		\item число доступных узлам адресов: $32 - 2 = 30$.
	\end{itemize}

	\item Подсеть \mintinline{text}{194.3.192.192/27}:
	\begin{itemize}
		\item адреса узлов: \mintinline{text}{194.3.192.193}~-- \mintinline{text}{194.3.192.222};
		\item широковещательный адрес: \mintinline{text}{194.3.192.223};
		\item число доступных узлам адресов: $32 - 2 = 30$.
	\end{itemize}

	\item Подсеть \mintinline{text}{194.3.192.224/27}:
	\begin{itemize}
		\item адреса узлов: \mintinline{text}{194.3.192.225}~-- \mintinline{text}{194.3.192.254};
		\item широковещательный адрес: \mintinline{text}{194.3.192.255};
		\item число доступных узлам адресов: $32 - 2 = 30$.
	\end{itemize}
\end{enumerate}

\section{Задание 2. Скорость Wi-Fi-соединений}

Требуется определить для двух устройств индекс MCS, вид модуляции и
отношение скоростей соединения Wi-Fi, используя таблицу соответствия
параметров стандарта IEEE 802.11ac.

Таблица, используемая для выполнения задания, приведена на
рис.~\ref{fig:80211ac-mcs-table}.

\img[1.0]{img/Screenshot 2026-10-12 at 07.58.10.png}
{Соответствие MCS, модуляции, скорости передачи, SNR и RSSI для IEEE 802.11ac}
{\label{fig:80211ac-mcs-table}}

Исходные данные для варианта 18:

\begin{itemize}
	\item устройство A: \mintinline{text}{RSSI = -52 dBm}, ширина полосы
	\mintinline{text}{40 MHz}, \mintinline{text}{MIMO 3};
	\item устройство B: \mintinline{text}{RSSI = -71.5 dBm}, ширина полосы
	\mintinline{text}{80 MHz}, \mintinline{text}{MIMO 3}.
\end{itemize}

Оба устройства подключены к одному маршрутизатору стандарта IEEE 802.11ac.
Параметры соединения настраиваются по наименьшим значениям, допустимым
для обоих устройств. Поэтому для расчёта принимаются ширина полосы
40 МГц и MIMO 3.

Поскольку устройства работают в одной
полосе и совместно используют её пропускную способность, полученную далее скорость для
каждого устройства необходимо будет разделить на два.

По таблице для полосы 40 МГц и защитного интервала 800 нс получаем параметры,
приведённые в табл.~\ref{tab:wifi-parameters}.

\begin{table}[H]
	\centering
	\caption{Параметры соединения устройств для полосы 40 МГц}
	\label{tab:wifi-parameters}
	\resizebox{\textwidth}{!}{%
	\begin{tblr}{
		colspec={Q[c,m] Q[c,m] Q[c,m] Q[c,m] Q[c,m] Q[c,m]},
		row{1}={font=\bfseries},
		hlines,
		vlines
	}
		Устройство & RSSI, dBm & MCS & Модуляция & Кодирование &
		Скорость одного потока, Мбит/с \\
		A & $-52$     & 9 & 256-QAM & $5/6$ & 180 \\
		B & $-71{,}5$ & 2 & QPSK    & $3/4$ & $40{,}5$
	\end{tblr}%
	}
\end{table}

С учётом трёх пространственных потоков и совместного использования полосы
скорость соединения устройства A равна

\[
	v_A = \frac{180 \cdot 3}{2} = 270\text{ Мбит/с},
\]

а скорость соединения устройства B равна

\[
	v_B = \frac{40{,}5 \cdot 3}{2} = 60{,}75\text{ Мбит/с}.
\]

Отношение скоростей соединений составляет

\[
	\frac{v_A}{v_B} = \frac{270}{60{,}75}
	= \frac{40}{9} \approx 4{,}44.
\]

Таким образом, скорость соединения устройства A с округлением до сотых в 4,44 раза
выше скорости соединения устройства B.

\section{Задание 3. Расчёт времени передачи файлов}

Требуется определить время передачи файла размером $A$ Мбайт при размере
кадра канального уровня $B$ байт и доле повторно передаваемых пакетов
$C/1000$.

При выполнении расчёта необходимо учитывать следующие условия:

\begin{itemize}
	\item в качестве протокола канального уровня используется Ethernet DIX,
	на сетевом уровне~--- IPv4, суммарный размер заголовков транспортного и
	прикладного уровней составляет 26 байт, физический уровень~--- 100BaseT;

	\item время передачи одного пакета данных составляет 89 мс; задержка перед
	повторной передачей пакета составляет 300 мс без учёта времени самой
	повторной передачи;

	\item повторная передача выполняется после передачи $1000/C$ пакетов;
	полученное значение округляется вверх до ближайшего целого числа.
\end{itemize}

Исходные данные для варианта 18:

\begin{itemize}
	\item размер файла: $A = 96$ Мбайт;
	\item размер кадра канального уровня: $B = 1255$ байт;
	\item параметр доли повторно передаваемых пакетов: $C = 9{,}17$.
\end{itemize}

Служебная часть каждого кадра включает 18 байт Ethernet DIX, 20 байт
заголовка IPv4 и 26 байт заголовков транспортного и прикладного уровней:

\[
	L_{\text{служ}} = 18 + 20 + 26 = 64\text{ байта}.
\]

Следовательно, объём данных файла в одном кадре составляет

\[
	L_{\text{данн}} = B - L_{\text{служ}} = 1255 - 64 = 1191\text{ байт}.
\]

Принимая $1$ Мбайт равным $2^{20}$ байт, получим число пакетов, необходимых
для передачи файла:

\[
	N = \left\lceil\frac{96 \cdot 2^{20}}{1191}\right\rceil
	= 84520.
\]

В среднем повторная передача выполняется после

\[
	N_{\text{инт}} = \left\lceil\frac{1000}{C}\right\rceil
	= \left\lceil\frac{1000}{9{,}17}\right\rceil = 110
\]

пакетов. Число полностью сформированных интервалов, а следовательно,
и число повторно переданных пакетов равно

\[
	N_{\text{повт}} = \left\lfloor\frac{84520}{110}\right\rfloor = 768.
\]

Время передачи одного кадра с учётом 8 байт преамбулы по физическому
уровню 100BaseT равно

\[
	t_{\text{кадр}} = \frac{(B + 8) \cdot 8}{100 \cdot 10^6}
	= \frac{(1255 + 8) \cdot 8}{100 \cdot 10^6}
	= 0{,}10104\text{ мс}.
\]

Полное время передачи складывается из времени передачи исходных и повторных
пакетов, времени передачи соответствующих кадров и задержек перед повторами:

\[
	T = (N + N_{\text{повт}})(89 + t_{\text{кадр}})
	+ N_{\text{повт}} \cdot 300.
\]

Подставляя полученные значения, имеем

\[
	\begin{aligned}
		T &= (84520 + 768)(89 + 0{,}10104) + 768 \cdot 300 \\
		  &= 7829649{,}49952\text{ мс} \\
		  &= 7829{,}64949952\text{ с}.
	\end{aligned}
\]

Округляя вверх до целого числа секунд, передача файла займёт
2 ч 10 мин 30 с.
